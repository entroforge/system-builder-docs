# 一项工作，为什么有三份记录

查阅阶段产物时，会遇到需求、运行状态和模块设计。它们分别记录承诺、进度与持续的设计，更新时机也不同。

| 想知道什么 | 查什么 | 取消订单的例子 |
| --- | --- | --- |
| 本次答应改变什么 | REQ | 顾客可取消本人未付款、未发货的订单，并知道结果 |
| 这项工作做到哪一步 | 运行状态 | 当前正在 S7，哪些检查完成，哪些问题待调查 |
| 订单能力如何设计 | 模块当前设计 | 原有下单与查看行为，以及新增取消的正常、拒绝和恢复路径 |

## REQ 保存一次承诺

AI 提出方案，人逐层确认 §A 的目标、§B 的方向、§C 的具体要求。确认稿被锁定后，成为设计与验收共同使用的需求基线。锁定表示承诺确定，工作启动的授权由 S1 另行记录。

## 运行状态保存当前进度

S1 将已锁定 REQ 绑定到本轮周期。`.claude/loop-state.json` 保存当前阶段、结果和证据引用。面向人的进度摘要应来自这份记录。

REQ 文件写着 `locked`，可以同时对应“尚未启动”“正在设计”或“正在验证”。实际位置要查运行状态。

## 模块设计随项目持续维护

订单能力会被后续需求继续修改。S2 更新受影响模块的完整当前设计，保留仍有效的旧行为，也加入新行为，并标明变化来自哪份 REQ。

下一项需求读取并更新同一模块设计。设计说明预期行为；代码是否实现、检查是否通过、功能是否上线，还需查看实现、验证和发布记录。

这三类记录的位置见[文档地图](../document-map/)，产生和使用它们的阶段见 [S0～S2](./intent)。
