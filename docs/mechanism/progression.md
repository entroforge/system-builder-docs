# 谁推动阶段，凭什么继续

阶段编号说明工作的位置。主协调者安排工作，AI 角色提交成果与检查结果，程序核对条件并登记下一步。

## 推进需要什么，留下什么

- **输入**：当前运行状态、这一阶段要求的确定版本、成果与检查证据，以及适用的授权。
- **输出**：条件满足后，运行机制登记合法的阶段变化，保存结果，并给出当前位置与下一步。条件不足时，给出缺项和处理方向。

这里的“运行状态”是 `.claude/loop-state.json` 中的当前事实。“阶段规则”在 `docs/control/loop-definition.json` 中规定允许的变化。负责执行校验和登记的程序叫 **Harness**，安装后的入口为 `.claude/bin/loop-harness`。

## 谁承担哪一部分

| 参与者 | 做什么 | 交给下一方的东西 |
| --- | --- | --- |
| 主会话中的协调者 | 读取当前位置，安排角色和任务，处理交接与阻塞 | 明确的工作范围、输入和完成标准 |
| 设计者或执行者 | 在范围内调查、设计、实现，提交真实结果 | 文档、代码、测试与工作证据 |
| 独立检查者 | 对照要求检查确定的对象，记录结论和发现 | 能追到对象、版本和范围的检查结果 |
| 程序机制 | 核对必要记录、引用、版本、授权及合法去向，保存事实 | 已登记的进度，或尚未满足的条件 |

**人**确认需求和本轮授权，处理目标、代价与风险的选择，并决定发布。S2 设计定稿、S3 契约锁定由 AI 规划角色完成，S8 修复约定由主协调者或架构角色批准。改变业务承诺或授权时，再交人决定。

需求锁定包含人的确认；技术产物锁定表示定稿，执行者据此工作，后续仍需独立检查。

## 一次正常推进怎样发生

以 S3 到 S4 为例，契约规划者完成并提交契约与模型，登记成果。工具操作触发的 **Hook** 按策略调用程序核对；满足规则后登记进入 S4，协调者开始组织任务规划。

Hook 是工具操作前后触发的检查与反馈。它把位置和缺项交给 AI；初始化、恢复和人的决定则走各自的操作入口。

条件不足时，团队按缺项补齐成果。进度摘要应转述已登记状态；需要返工时，按正式路径处理。

## 程序核对的边界

程序可以核对引用是否存在、版本是否一致、必要检查是否有记录。设计能否解决问题、证据是否充分解释结果，需要 AI 的专业判断与独立审查；是否值得交付，由人判断。

任务登记、Agent 实际启动和成果交回，需要各自的回执。具体平台的自动触发与启动能力，以安装版本的指南和实际结果为准。

工作中断或承诺改变时，继续阅读[暂停、修订与下一项需求](./lifecycle)。
