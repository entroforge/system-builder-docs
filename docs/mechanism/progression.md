# 谁推动阶段，凭什么继续

阶段编号说明工作的位置。让下一步发生，还需要有人组织工作、有人提交成果，以及程序核对推进条件。

## 推进需要什么，留下什么

- **输入**：当前运行状态、这一阶段要求的确定版本、成果与检查证据，以及适用的授权。
- **输出**：条件满足后，运行机制登记合法的阶段变化，保存结果，并给出当前位置与下一步。条件不足时，给出缺项和处理方向。

这里的“运行状态”是 `.claude/loop-state.json` 中的当前事实。“阶段规则”在 `docs/control/loop-definition.json` 中规定允许的变化。负责执行校验和登记的程序叫 **Harness**，安装后的入口为 `.claude/bin/loop-harness`。

## 谁承担哪一部分

| 参与者 | 做什么 | 交给下一方的东西 |
| --- | --- | --- |
| 主会话中的协调者 | 读取当前位置，安排角色和任务，处理交接与阻塞 | 明确的工作范围、输入和完成判据 |
| 设计者或执行者 | 在范围内调查、设计、实现，提交真实结果 | 文档、代码、测试与工作证据 |
| 独立检查者 | 对照要求检查确定的对象，记录结论和发现 | 能追到对象、版本和范围的检查结果 |
| 程序机制 | 核对必要记录、引用、版本、授权及合法去向，保存事实 | 已登记的进度，或尚未满足的条件 |

**人**确认需求和本轮授权，处理涉及目标、代价与风险的选择，并作发布决定。S2 的设计收口、S3 的契约锁定，由相应 AI 规划角色完成；S8 的修复约定由主协调者或架构角色审定。若这些选择改变业务承诺或授权边界，就需要交回人。

因此，“锁定”在不同对象上含义不同：需求锁定包含人的确认；技术产物锁定表示本轮设计已经收口，后续执行应依据这个版本。技术产物仍要接受独立检查。

## 一次正常推进怎样发生

以 S3 到 S4 为例，契约规划者先完成并提交契约与所需模型，登记对应成果。工具操作触发的 **Hook** 会按策略调用机制，核对当前输入和条件；满足后登记进入任务规划，主协调者再依据新状态组织 S4。

Hook 可以理解为“工具操作前后自动执行的检查”。它还会把当前位置和缺项反馈给 AI。一般工作沿这些触发点推进；初始化、恢复和人的决定另有明确入口。

条件不足时，团队继续补充缺失的成果。把进度摘要写成“已进入 S4”，不会替代正式登记；人工定位偏差后，也应走相应返工路径。

## 程序核对的边界

程序可以核对引用是否存在、版本是否一致、必要检查是否有记录。设计能否解决问题、证据是否充分解释结果，需要 AI 的专业判断与独立审查；是否值得交付，由人判断。

本站解释模板规定的工作逻辑。具体平台的自动触发和 Agent 启动能力，需要结合所安装版本的指南与实际回执核对。运行记录中的任务登记，只说明任务已登记。

工作中断或承诺改变时，继续阅读[暂停、修订与下一项需求](./lifecycle)。
