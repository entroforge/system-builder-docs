# 测试如何检查交付结果

测试工作把“应该发生什么”与“实际发生什么”对照起来。AI 可以设计检查、运行测试、独立审查并调查异常；它的结论需要能指向检查对象和证据。人据此了解已证明的结果和仍未解决的问题。

## 检查从动工前开始

**S5** 先检查契约和任务：需求有没有遗漏，设计与接口是否一致，任务能否交付相应条款。把这些矛盾提前找出来，后续实现才有可靠依据。

**S7** 则检查实际共同版本，分别关注是否符合要求、工程质量是否达标、真实用户路径是否走通。开发者会运行自己的测试；完整验证还需要与产出者分开的角色取得证据。

## 允许与拒绝都要有结果

取消订单的检查既要证明符合条件时可以成功，也要证明已发货或权限不足时会正确拒绝，并保留应有的数据状态。页面显示了成功提示，还须核对业务结果确实成立；失败时也要检查反馈和恢复路径。

检查依据来自需求、设计和契约。AI 可以补充遗漏的测试情形、选择验证方法，发现承诺不清楚时提出问题；改变验收标准需要回到相应的确认流程。

## 修复以后重新取得证据

**S9** 的定向复验检查原问题是否解决，之后还要回 **S7** 开启完整验证。**S10** 再将各项要求与有效证据汇总。这样可以查清哪一版检查过哪些情形，也能看到修改使哪些旧结论失效。

测试侧主要查[审查、QA 和浏览器报告](/document-map/reports)，并沿报告回到需求与模块场景。完整验证机制见 [S6～S7](/mechanism/build-and-check)，复验与返回路径见 [S8～S9](/mechanism/investigate-and-repair)。
