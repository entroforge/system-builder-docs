# 测试如何检查交付结果

开发交回了共同版本，测试将实际结果与要求对照。AI 可以设计检查、运行测试并记录发现；人根据证据判断结果和剩余风险。

## 动工前后，检查对象不同

S5 检查契约和任务：要求有没有遗漏，设计与接口是否一致，工作能否按计划交付。S7 检查实际软件，包含三种视角：

| 检查视角 | 取消订单时检查什么 |
| --- | --- |
| 是否符合约定 | 本人且符合状态条件时允许取消；无权或已发货时拒绝 |
| 工程质量 | 状态是否可靠保存，测试是否覆盖必要情形，代码与安全要求是否满足 |
| 真实使用路径 | 从页面进入、提交、看见反馈，再重新打开订单，过程是否符合设计 |

开发者会检查自己的工作；S7 还需要与产出者分开的角色取得证据。符合条件时成功、被拒绝时不改数据、出错后能够按设计恢复，都需要检查。

## 结论带上对象和范围

“测试通过”应能指到确定版本、执行过的情形和实际结果。未执行的必需情形仍是缺口；不适用的项目需要理由和独立审查。

AI 可以补充检查、选择方法；若需要改变已经确认的验收标准，则回到需求确认流程。人可以从[一条承诺](../document-map/evidence-chain)查起，看看当前证据是否支持它。

## 修复后重新验证

S9 定向复验原问题，之后回 S7 开启新一轮完整验证；S10 将有效证据与各项要求汇总。局部修好以后，也要检查改动有没有影响其他部分。

材料位置见[检查与验收](../document-map/reports)，完整验证条件见 [S6～S7](../mechanism/build-and-check)。
