# 开发如何设计和实现

开发工作把已确认的要求变成能够协同运作的软件。它包括技术设计、接口约定、任务安排、实现与集成，也包括发现问题后的调查和修复。AI 可以承担这些专业工作，并在既定目标和约束内选择办法。

## 先解决各部分怎样配合

**S2** 确定模块职责、数据与状态；**S3** 写清各部分共同遵守的契约；**S4** 再拆任务和依赖。这样的安排让并行工作有共同依据。

取消订单时，页面要显示操作结果，服务端要判断状态和权限，数据要保留正确变化。三部分先约定同一种“成功”和“拒绝”，才能各自实现。**S5** 由独立角色检查这些约定与任务是否一致、可执行。

## 给 AI 范围内的设计空间

模块怎样组织、接口如何实现、测试怎样编写，可以由 AI 调查现有项目后选择，并记录必要的理由。人提供用户承诺、费用和时间等约束，重点判断方案的代价是否可接受。

选择若需要改变承诺，就应回到人。例如内部如何防止重复取消属于工程设计；放宽取消条件、删去已确认的验收要求或引入新的付费依赖，则需要明确相应的业务或预算决定。

## 实现完成还需要交接

**S6** 完成代码、测试与集成，成果进入共同版本后再接受独立验证。出现问题时，**S8** 先调查原因和影响，**S9** 在修复边界内改动，并重新检查受影响的结果。

人可以从设计依据、任务边界、集成结果和阻塞原因了解开发进度。需要查技术分工，进入[架构目录](/document-map/architecture)；需要查执行约定，进入[合同与任务](/document-map/dev)。具体阶段见[设计与计划](/mechanism/plan)、[构建](/mechanism/build-and-check)和[调查修复](/mechanism/investigate-and-repair)。

这些关系在 Git 中怎样体现，可沿[一行变更的示范](../start/git)查看起点、分支、共同版本，再看[冲突与发布](../start/git-decisions)。
