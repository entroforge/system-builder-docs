# 打开项目的 `docs/`

[工程协作](/engineering/)中的交接会留下需求、设计、任务和检查结果。这些材料按用途放进项目的 `docs/`。先知道有哪些材料、各自回答什么，再按需要打开具体文件。

`go-system-builder` **模板仓库**主要提供空白模板、规则、指南与示例。安装到实际开发的**目标项目**后，团队才会写出这个项目自己的成果。目录存在，不代表工作已经完成。

## 从目录看出编排逻辑

| 在项目中想弄清 | 进入哪一层 |
| --- | --- |
| **承诺了什么** | [`requirements/`](./requirements)：目标、范围、具体要求与验收 |
| **产品怎样呈现** | [`design/`](./design)：整体设计语言，以及各模块的故事、动线和 HTML 原型 |
| **系统怎样承担** | [`architecture/`](./architecture)：模块职责、数据、状态与流动 |
| **怎样交接工作** | [`dev/`](./dev)：前后端及联调合同、单项任务和整体计划 |
| **实际检查到了什么** | [`reports/`](./reports)：审查、质量、浏览器路径、缺陷、验收与发布审计 |
| **工作允许怎样推进** | [`control/`](./control)：阶段协议、合法迁移与受保护操作 |
| **遇到具体工作遵守什么约束** | [`rules/`](./rules)：变更、Git、安全、原型、缺陷等稳定规则 |
| **操作和背景怎么查** | [`guides/`](./guides)：安装、入门、概念与工程说明 |
| **完整样子是什么** | [`examples/`](./examples)：合成的共享模型、任务与报告样例 |

前五个目录保存项目成果，后四个目录提供规则和学习材料。想知道一份文件在哪一步产生、依据什么输入，进入[机制原理](/mechanism/)。

## 根目录的四个入口

| 文件 | 用途 |
| --- | --- |
| `docs/README.md` | 从整个工程文档进入各目录 |
| `docs/DOCUMENT-MAP.md` | 简短说明每类文档的职责与权威范围 |
| `docs/project.yaml` | 项目配置：目标、参与者、技术栈和约定路径等 |
| `docs/project-map-template.md` | 面向人的项目概况模板；目标项目填写后成为 `docs/project-map.md` |

`project-map.md` 提供项目概况与进度摘要。当前绑定的 REQ、阶段和证据状态，以 `docs/` 外的 `.claude/loop-state.json` 为准。实际代码和测试保存在项目的代码目录。

## `docs/` 与运行环境怎样配合

安装后的项目还会有以下入口：

| 位置 | 在目标项目中的作用 |
| --- | --- |
| 根目录 `AGENTS.md` | 给 AI 的项目边界与查阅入口 |
| `docs/` | 已确认的要求、设计、工作约定、报告及共同规则 |
| 项目的代码与测试目录 | 实际软件与可执行检查；具体路径取决于项目 |
| `.claude/skills/`、`.claude/agents/` | AI 的工作方法与角色定义，由安装资产提供 |
| `.claude/bin/loop-harness`、Hook 配置 | 核对推进条件、执行运行控制和反馈 |
| `.claude/loop-state.json` 及相应日志、归档 | 当前事实，以及可追查的工作历史 |

会话中断后，AI 读取状态与相关文档继续工作。运行规则的位置见[运行定义](./control)，实际推进过程见[谁推动阶段](../mechanism/progression)。

## 材料会保留多久

| 存续范围 | 代表材料 | 下一项需求怎样使用 |
| --- | --- | --- |
| **随项目持续维护** | 项目配置、架构、整体设计语言、模块当前设计、共享数据定义、代码与稳定规则 | 读取当前版本，按新需求更新受影响部分 |
| **对应一项变化** | REQ、该 REQ 的合同与任务索引、验收和发布材料 | 保留这次承诺与交付历史；下一项另有自己的记录 |
| **对应一次检查或修复** | 验证计划、结果、缺陷调查、修复与复验依据 | 核对版本和适用范围；旧结果不能直接充当新周期证据 |

周期结束后按授权归档运行记录，项目资产继续维护。具体处理见[暂停、修订与下一项需求](../mechanism/lifecycle)。

## 同一目录里，材料的身份可能不同

`REQ-template.md` 是空白样板，`REQ-{id}.md` 是项目填写的需求；`examples/` 中的 `REQ-042.md` 仍是示例。报告则记录某个版本、某次检查的结果。阅读前先分清材料身份。

目录里的材料怎样连起来，见[从承诺查到证据](./evidence-chain)。
