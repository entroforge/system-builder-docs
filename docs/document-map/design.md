# `design/`：产品怎样被看见和使用

`docs/design/` 保存体验设计。它同时容纳**跨需求沿用的产品语言**和**某个模块当前的页面与行为**。这两类资料放在一处，是为了让新页面能继承产品整体设计，同时保留对具体需求的回应。没有可见界面的项目，可能暂时不会产生其中的大部分文件。

## 先看目录分工

| 位置 | 内容 | 查阅时机 |
| --- | --- | --- |
| `DESIGN.md` | 产品整体的设计方向、关系、约束和适用界面 | 想了解产品为什么呈现为现在的样子 |
| `design-language.md`、`tokens/` | 可复用的版式、颜色等设计规则；`tokens.json` 是取值来源，`tokens.css` 供页面使用 | 想核对视觉细节是否属于同一套语言 |
| `research/` | 设计方向依据的用户与业务证据，按需建立 | 想追问某个方向基于哪些观察 |
| `surface-profiles/` | 第二类界面出现时的差异说明，按需建立 | 同一产品有不同使用场景时 |
| `proof/` | 风格样稿、关键页面与关键流程的 HTML 证明 | 想看整体设计语言是否能落到真实场景 |
| `decisions/` | 方向选择、例外、组件或模式提案 | 想知道某项设计为何被采纳、偏离或推广 |
| `derivation/REQ-{id}.md` | 某项需求如何继承或改变既有设计 | 想追踪一次界面变化的来由 |
| `prototypes/<module>/` | 某模块目前完整的故事、动线、情形与 HTML 页面 | 想评审具体页面和用户行为 |
| `NA-checklist-template.md` | 某项界面检查确实不适用时的说明样板 | 需要解释为什么不做某项检查 |

`proof/` 下按 `style-tiles/` 风格样稿、`anchor-screens/` 关键或压力页面、`golden-flows/` 关键流程再分一层，用于检验**整体设计语言**。`decisions/` 则分别保存方向决定、带期限的例外、组件或模式提案。`prototypes/<module>/` 描述**模块当前应有的产品行为**：前者可以只挑关键场景，模块原型则要覆盖仍然成立的正常与异常情形。

## 打开一个模块原型包

以订单模块为例，目录可以叫 `docs/design/prototypes/orders/`。`orders` 是示例名称；真实项目按模块命名。一个模块维护一套当前设计，新 REQ 会更新这套设计，不会复制出一份“某 REQ 专属原型”。

| 文件 | 读到的内容 |
| --- | --- |
| `index.html`、`*.html` | 页面入口，以及当前页面、对话框、向导和可见状态。评审原型从入口打开 |
| `assets/` | 这一组原型使用的图片、图标和其他本地素材 |
| `stories.md` | 谁在什么情境下，为了什么目标使用模块；也包含失败、拒绝和恢复的故事 |
| `flows.md` | 从入口到结果的具体操作路线：前置条件、每一步动作、可见反馈与终点 |
| `scenario-model.json`、`cross-matrix.json` | 业务事实、规则、允许与拒绝分支，以及这些分支怎样覆盖需求和故事 |
| `cases.json`、`scenario-coverage.json` | 由场景模型生成的检查情形与覆盖情况 |
| `fixture-contract.json` | 为检查准备可重复使用的数据及清理约定 |

因此，口语中的“原型图”在这里通常是**可打开的 HTML 页面**；页面用到的图片放在同一模块的 `assets/`。一张截图能展示一个时刻，完整原型还要交代按钮之后、出错时、无权限时发生什么。

## 故事与动线各记录什么

`stories.md` 从**人的目标**出发。一条故事写明角色、触发情境、想完成的事、开始前的条件，以及成功、被拒绝或需要恢复时的体验；它还指回 REQ，并说明相应原型区域。比如“顾客发现订单不再需要，希望自行取消并知道结果”。读这份文件，主要判断**有没有考虑到相关的人和处境**。

`flows.md` 把这些故事变成**可逐步走通的路径**。每条 `PATH-*` 有入口、前置数据、操作顺序、每一步看见的结果和终点。取消成功、订单已发货而被拒绝、提交失败后重试，会是不同路径。读这份文件，主要判断**从页面进入到离开，过程是否完整**。

HTML 原型呈现用户实际会看到的东西；故事解释为何需要这些情形；动线检查情形能否从头走到尾。场景模型与用例再把允许、拒绝和覆盖关系固定下来。三者指向同一个模块，才能避免“画面看起来完整，实际少了一条关键路径”。

有界面变化的 REQ 可先看 [`requirements/`](./requirements) 的 §C，再看 `derivation/REQ-{id}.md` 与受影响模块的原型包；技术模块和数据流属于 [`architecture/`](./architecture)。
